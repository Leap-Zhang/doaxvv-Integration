# DOAXVV 攻略站 · 项目书

> 项目名称：《死或生 沙滩排球：维纳斯假期》（DEAD OR ALIVE Xtreme Venus Vacation，简称 DOAXVV）攻略站点
> 文档性质：项目总纲（面向项目经理 / 开发者 / 验收方）
> 版本：V2（正式纳入官方站 game.doaxvv.com 作为权威释义与校订源）

---

## 1. 项目概述

### 1.1 项目是什么

一个面向《DOAXVV》玩家（中文为主）的**静态攻略站**，覆盖：女孩图鉴、泳装图鉴、技能图鉴、系统机制指南、社区攻略、常用工具与术语表。目标是把社区零散信息 + 官方释义 + 数值数据整合成一个**可检索、可收藏、可本地离线使用**的百科式站点。

### 1.2 项目定位

- 数据驱动：以 `doax.cc` 的数值/图鉴数据库为**主数据源**。
- 权威校订：以官方站 `game.doaxvv.com` 的 Help / 角色资料 / 制作名单为**官方释义源**。
- 社区补充：以百度贴吧等社区攻略为**玩法与实战内容源**。
- 全程本地化：所有数据与图片**本地化进仓库**，不依赖运行时外部请求。

### 1.3 一句话目标

做一个「数据来自 doax.cc、释义对照官方、玩法来自社区、可离线检索收藏」的 DOAXVV 中文攻略站。

---

## 2. 核心目标与非目标

### 2.1 核心目标

1. **内容完整**：女孩 / 泳装 / 技能三大图鉴齐全，命中社区主流需求。
2. **系统可读**：把官方 Help 的六大模块（主界面、挑战赛、泳装/饰品/声援板、岛主、女孩、拍摄）清洗成可检索的系统指南。
3. **工具可用**：面板估算、满破 PP 规划等实用小工具能落地。
4. **体验友好**：海岛度假清新风、深色模式、三语切换（UI + 数据），移动端可用。
5. **可部署**：静态产物 + GitHub Pages（或等效静态托管），一键发布。

### 2.2 非目标（明确不做）

- ❌ 不做正文（指南/攻略/图鉴描述）的英、日双语翻译——三语只覆盖 UI 与数据字段，内文冻结。
- ❌ 不做「日服 / 国际服（Steam）」数值区分——已取消该分化，数值以单一口径展示。
- ❌ 不做在线数据库 / 登录 / 用户生成内容——保持纯静态。
- ❌ 不做官方站 JS 渲染层的实时抓取与同步——只取静态可抓层，其余靠人工/脚本一次性治理。

## 3. 数据来源与治理（重点）

### 3.1 数据源清单

| 数据源 | 类型 | 用途 | 抓取方式 | 本地化位置 |
|---|---|---|---|---|
| `doax.cc` | 数值/图鉴数据库 | 女孩、泳装(SSR)、技能的**主数据** | API / 仓库 `doaxvv_bromide` | `src/data/*.json`、`public/data/*` |
| `github.com/doaxcc/doaxvv_bromide` | 图鉴打包仓库 | 立绘、泳装图、场景图 | 图片仓库拉取 | `public/img/`（WebP） |
| `game.doaxvv.com`（官方） | 官方 Help / 角色 / 名单 | **玩法释义、女孩设定、CV、系统说明的权威校订** | 静态抓取（Help 六大模块、`/cn/help.html`、`characters/cNN.html`、`staff.html`） | `src/data/official/*`（建议） |
| 百度贴吧（社区） | 攻略文字 + 配图 | 玩法、配装、活动攻略 | 页面抓取并本地化 | `src/content/`、`public/img/community/` |

### 3.2 官方站定位（本次新增核心）

官方站 `https://game.doaxvv.com/` 性质为**营销 + 官方帮助文档站**，根路径与部分页面是 **JS SPA 壳**，静态请求只能拿到有限内容。经实际分析：

- ✅ **可直接静态抓取**：
  - `/cn/help.html`、`/en/help.html`：合并版帮助文档（全文）。
  - `/production/html/information/help_{home,fes,swim,owner,girl,shooting}_{cn,en,tw,ko}.html`：六大模块分页。
  - `game-test.doaxvv.com/{lang}/cNN.html`、`doax-venusvacation.jp/cNN.html`：角色基础资料（年龄/身高/三围/血型/职业/兴趣/生日）。
  - `/tw/staff.html`：制作人员与 CAST（声优）名单。
  - `/production/html/information/info_gl_*.html`、`gacha_gl_*.html`：公告/卡池页。
- ⚠️ **JS 壳，需无头浏览器渲染**：根路径 `/`、`/cn/characters.html`（角色轮播）、`/production/html/information/help_cn.html`（旧版聚合）。
- ❌ **官方站没有泳装/技能数值**：数值一律以 `doax.cc` 为准。

> 结论：官方站作为「字面释义 + 设定校订」的可信第二源，**不承担数值与图片主源**，故不阻塞现有攻略站架构。

### 3.3 本地化与一致性原则

- 全仓库采用本地 JSON / 内容文件，构建期读取，不依赖运行时外链。
- 图片统一转 **WebP**（当前约 71 个文件 / ~7MB），控制体积。
- 多语言：UI 与数据字段支持中/英/日；正文（指南、攻略、描述）保持中文，三语不再扩展内文。
- 取消日服/国际服分化后，`steam` 字段保留为冗余，不再渲染为独立口径。

### 3.4 数据更新策略

- 提供 `tools/doax/` 下生成与治理脚本（`gen_from_api.cjs`、`gen_servers.cjs`、`gen_doax.cjs`、`map_bromide.cjs`、`update.mjs`、`optimize-images.cjs`）。
- 提供 `.github/workflows/update-data.yml`（定时拉取 R6 数据）与 `images:check` 图片治理脚本。
- 官方 Help 为低频内容，按季度人工对账一次即可（不建议做成高频同步）。

## 6. 功能设计

- **检索**：女孩 / 泳装 / 技能全局搜索。

## 9. 图片与素材策略（治理）

- 立绘（女孩、泳装）：来自 `doaxvv_bromide` 仓库，转 WebP，本地化到 `public/img/`。
- 场景图、宣传图：本地化入库。
- 社区攻略配图：贴吧抓取后一并本地化（`public/img/community/`）。
- 图片治理脚本 `tools/optimize-images.cjs` + `pnpm images:check` 用于压缩与检查。

## 10. 部署与运维

- GitHub Pages + `.github/workflows/deploy.yml`。
- `astro.config.mjs` 读取 `process.env.BASE_URL || '/'`，适配子路径部署。
- `.github/workflows/update-data.yml` 定时同步数据。
- `public/.nojekyll` 已配置，避免 Jekyll 干扰静态产物。
- 本地预览：`pnpm build` → `node node_modules/astro/astro.js preview --port 4321`。

> **待办**：仓库目前无 GitHub 远端、无 `gh` 凭据。首次部署需用户提供远端仓库或配置推送凭据后触发 CI。

## 12. 风险与限制

| 风险 | 影响 | 应对 |
|---|---|---|
| 官方站根路径 / 角色页为 JS 壳 | 静态抓取拿不到 | 限定抓取静态可抓层；角色轮播等按需用无头浏览器 |
| 版权归属 | 立绘 / 攻略图归属厂商与原作者 | 仅作学习/攻略用途，标注来源；不当商用 |
| 数据口径漂移（官方与社区不一致） | 图鉴数值存疑 | 以 `doax.cc` 为数值主源，官方仅作释义校订 |
| 部署凭据缺失 | 无法上线 | 用户提供远端仓库与推送凭据 |
| 图片体积增长 | 构建/加载变慢 | WebP 压缩 + 图片治理门禁 |

## 13. 验收标准

1. `pnpm build` 通过，产出全部页面（含 SEO 文件）。
2. 女孩 / 泳装 / 技能三大图鉴数据完整可检索。
3. 官方 Help 释义已接入系统指南与女孩「官方释义」栏（P6）。
4. 三语 UI + 数据可切换；正文保持中文。
5. 图片为本地 WebP，体积受控。
6. 可一键部署到 GitHub Pages 并通过链接访问。
7. 侧边栏 / 导航无定位或重复引用 bug。
